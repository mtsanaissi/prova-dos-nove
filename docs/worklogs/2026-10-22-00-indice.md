## Reprodução

```sh
uv venv .venv
uv pip install -r requirements.txt

.venv/bin/python scripts/01_inventory_seedf.py
.venv/bin/python scripts/02_download_seedf.py
.venv/bin/python scripts/03_profile_seedf.py
.venv/bin/python scripts/04_crosswalk.py
.venv/bin/python scripts/05_external_sources.py
.venv/bin/python scripts/06_analysis.py

# INEP: baixar no navegador, depositar em data/raw/inep/inbox/
.venv/bin/python scripts/07_ingest_inep.py
.venv/bin/python scripts/08_profile_inep.py
```

`01`–`04` e `06` são offline (leem `data/`). `02` e `05` acessam a rede, são
idempotentes por tamanho declarado e param sozinhos quando o arquivo já existe.
`07` é o único passo com intervenção humana (o download da INEP só funciona pelo
navegador — ver registro 01).

## O que a sessão decidiu

1. Recorte DF desde o começo; microdado nacional só depois de medir tamanho,
   filtrar e documentar. Nada de download de 5,4 GB de duplicatas.
2. Três estados mantidos separados ponta a ponta: `0`, ausente e não aplicável.
   O perfil lê tudo como texto justamente para não colapsar isso.
3. Taxa de casamento medida antes de qualquer join; nenhum join por nome.
4. INEP entra por caminho manual declarado, nunca simulando download automático.
5. Exceção documentada: a planilha de Ideb por UF mantém as 27 UFs porque sem
   elas não existe comparação — o recorte DF-only vale para microdado.
